## ❓ 常見問題解答 (FAQ)

### 1. 分身會影響原有 App 的資料嗎？
**絕對不會。**

ATBClone 在設計上實現了嚴格的物理級隔離與沙盒容器隔離：

* 原版母體應用依然讀取並寫入系統預設的真實路徑（如 `~/Library/Application Support/` 或 `~/Library/Containers/<原BundleID>`）。
* 分身應用被限定在其專屬的隔離目錄中執行（如 `~/ATBClone/Data/<分身名称>/`）。
* 兩者同時執行互不搶佔本地 SQLite 資料庫檔案，互不覆蓋配置，互不汙染快取。

---

### 2. 分身的資料存放在哪裡？如何備份與遷移？
預設情況下，所有分身的使用者資料（本地聊天記錄、資料庫、Cookie、首選項與快取檔案）均存放在您的使用者目錄下：
`~/ATBClone/Data/<分身名称>/`

```text
~/ATBClone/
├── config.yaml           # 全局偏好设置
├── clones.yaml           # 已创建分身元数据注册表
├── recipes/              # 用户自定义规则库
└── Data/
    ├── WeChat2/          # 微信分身 2 的专属数据目录
    │   ├── Home/         # 伪装的 $HOME 目录
    │   └── Tmp/          # 专属临时目录
    └── Telegram-Work/    # Telegram 工作分身数据目录
```

#### 如何備份與遷移：
* **資料備份**：直接將 `~/ATBClone/Data/<分身名称>` 資料夾複製或壓縮打包備份至行動硬碟或網盤。
* **換機遷移**：在新 Mac 上安裝好 ATBClone，將舊電腦的 `~/ATBClone/` 整個目錄複製至新電腦相同路徑下，然後使用相同名稱重新克隆一次應用，原有的聊天記錄與登入態將被直接識別！

---

### 3. 會被官方封禁賬號嗎？
**ATBClone 執行在純粹的 macOS 作業系統環境層。**

* **零逆向篡改 / 零記憶體注入**：ATBClone **不會**注入任何動態連結庫（如 Frida、Cycript、Xposed 等 Hook 工具），**不會**修改應用記憶體或攔截網路資料包，也**不會**篡改編譯好的 Mach-O 機器指令。
* **純淨環境欺騙**：應用本體以原版邏輯執行，只是被重定向了 `$HOME` 家目錄並賦予了新的合法 Bundle ID。
* **單應用獨立 IP 代理**：通過為分身配置獨立的 HTTP 或 SOCKS5 代理，不同分身可使用完全獨立的公網 IP 訪問伺服器，有效避免多賬號在同一 IP 下的高頻關聯風險。

> [!IMPORTANT]
> 雖然 ATBClone 提供了最乾淨安全的作業系統級隔離，但您仍需遵守各平臺的使用者協議，切勿利用多開進行批次群發、違規外掛或自動化惡意行為。

---

### 4. 需要管理員密碼 (Root / Sudo) 嗎？
* **安裝到 `~/ATBClone/Apps`（預設推薦）**：**全程無需管理員密碼，免 Root 許可權。** 所有檔案均執行在當前普通使用者空間中。
* **安裝到系統全域性 `/Applications`**：macOS 會彈出一次系統原生授權視窗，要求輸入開機密碼以允許向全域性系統目錄寫入檔案。

---

### 5. 開啟分身提示“已損壞，無法開啟”怎麼辦？
這是因為 macOS Gatekeeper（門禁系統）為修改過簽名的應用打上了隔離擴充套件屬性（`com.apple.quarantine`）。

#### 解決方法：
開啟 macOS 終端（Terminal），執行以下命令清理隔離屬性：
```bash
xattr -cr "/path/to/您的分身应用.app"
```
或者在 ATBClone 主介面中選中該分身，點選 **"更新"**，引擎將自動為您清除隔離屬性並重新完成 Ad-Hoc 簽名。

---

### 6. 如何為分身更換自定義圖示？
1. 在訪達中開啟 `~/ATBClone/Apps`，找到您的分身應用。
2. 選中分身並按下快捷鍵 `Cmd + I`（顯示簡介）。
3. 將您準備好的 `.icns` 或 `.png` 圖示檔案，直接拖拽到簡介視窗左上角的小圖示上即可完成替換。

---

### 7. 微信/QQ 等通訊分身如何在選單欄顯示圖示並正常接收訊息提醒？

微信、QQ 等即時通訊軟體支援在 macOS 頂部選單欄駐留圖示並在後臺持續接收新訊息。

#### 1. 開啟選單欄圖示顯示：
* 登入分身微信後，按下快捷鍵 `Cmd + ,` 或在頂部選單選擇 **微信 -> 設定**（Settings）。
* 進入 **通用**（General）設定頁面，勾選 **「在選單欄顯示微信圖示」**（Show WeChat in Menu Bar）。
* ATBClone 引擎會在分身首次啟動時自動繼承母體微信的基礎偏好設定，若母體已開啟該選項，分身將自動開啟。

#### 2. 後臺訊息接收機制與通知：
* **後臺長連線**：由於分身使用 Ad-hoc 重簽名，macOS 的 Apple 官方遠端推送（APNs）無法直接路由至分身，但微信在後臺執行時會通過自身獨立的 TCP 長連線（`LongLink`）即時接收所有私聊與群聊訊息。
* **保持後臺執行**：日常使用時，直接點選主視窗紅色的「關閉」（`x`）按鈕即可關閉視窗，微信分身將繼續在選單欄和後臺駐留執行，**切勿使用 `Cmd + Q` 徹底退出**。
* **訊息提醒效果**：當收到新訊息時，選單欄分身圖示將顯示未讀提示（紅點/動畫），程式塢（Dock）圖示將顯示未讀數字徽標，並伴隨提示音。
* **系統通知許可權**：首次執行分身微信時，若系統彈出「是否允許 WeChat 傳送通知」，請點選「允許」。亦可前往 macOS **系統設定 -> 通知** 中確認已為分身應用開啟通知橫幅與聲音提示。

> [!TIP]
> **底層保障**：微信、QQ 等通訊軟體依賴 ATBClone 的 **`dylib` 原生動態庫注入模式**（建立分身時請保持 `auto` 或選擇 `dylib`），以避免 `execv` 導致程序版本號改變而破壞 macOS 通知中心 (`usernoted`) 與狀態列 (`MenuBarAgent`)。如果誤選為 `launcher` 模式，通知橫幅和選單欄圖示可能會被系統靜默遮蔽。

## 🩺 系統環境體檢 (Doctor 工具)

如果分身在建立或簽名時遇到異常，可以使用內建的 **Doctor (系統體檢)** 工具排查底層依賴：

```text
+-------------------------------------------------------------+
|  🩺 系统环境体检 (System Doctor)                            |
|                                                             |
|  环境自检项目:                                              |
|  [✔] 处理器架构: Apple Silicon (arm64)                      |
|  [✔] Xcode 命令行工具: 已正确安装 (/Library/...)             |
|  [✔] 代码签名组件 (codesign): 正常可用                      |
|  [✔] Plist 处理器 (PlistBuddy): 正常可用                     |
|  [✔] 应用程序目录权限: 读写正常                             |
|  [✔] 数据存储目录权限: 读写正常                             |
|                                                             |
|  [ 重新体检 🔄 ]                                            |
+-------------------------------------------------------------+
```

1. 點選 ATBClone 側邊欄的 **"系統體檢"**（`🩺`）圖示。
2. 探針將自動校驗：
   * **Xcode Command Line Tools (`xcode-select -p`)**：確保 Apple 開發者編譯工具已安裝，這是 `codesign` 簽名的必要條件。
   * **Codesign 與 PlistBuddy**：確認系統底層工具鏈可用。
   * **目錄讀寫許可權**：檢查 `~/ATBClone/Apps` 和 `~/ATBClone/Data` 的寫入許可權。
3. 若某一項出現紅色警告，根據介面提示進行修復即可（如終端執行 `xcode-select --install`）。

## 🐛 發現問題與 GitHub 提報指引（標準排錯流程）

如果您在多開某個特殊軟體時發現**無法完成分身**，或者**分身後開啟閃退/報錯**，請通過以下標準流程提取診斷資訊並提交 GitHub Issue：

### 第一步：在主介面選中異常分身並點選“詳情”
1. 開啟 ATBClone 主介面。
2. 在卡片檢視或表格檢視中，選中出現故障的分身應用。
3. 點選 **"詳情"**（`ℹ️` / `详情`）按鈕開啟“分身詳情”視窗。

```text
+-------------------------------------------------------------+
|  ℹ️ 分身详细信息 - WeChat2                                  |
|                                                             |
|  基础配置:                                                  |
|  • 母体应用:   /Applications/WeChat.app                     |
|  • 原始 ID:    com.tencent.xinWeChat                        |
|  • 新分身 ID:  com.tencent.xinWeChat.atbclone.WeChat2       |
|  • 克隆策略:   hard_clone                                   |
|  • 安装目标:   /Users/username/ATBClone/Apps/WeChat2.app     |
|  • 数据目录:   /Users/username/ATBClone/Data/WeChat2        |
|  • 代理设置:   http://127.0.0.1:7890                        |
|                                                             |
|  注入参数与运行环境:                                        |
|  • 启动参数:   --user-data-dir=...                          |
|  • 环境变量:   HOME=..., TMPDIR=...                         |
|  • 执行命令:   env HOME=... /path/to/WeChat.bin             |
|                                                             |
|  [ 关闭 ]                                                   |
+-------------------------------------------------------------+
```

---

### 第二步：複製“分身詳情”對話方塊中的應用資訊
“分身詳情”對話方塊中清晰列出了該分身的核心執行引數與配置：

* **基礎資訊**：母體路徑、變異後的新 Bundle ID、克隆策略與資料儲存路徑；
* **注入引數**：透傳給二進位制的命令列引數；
* **環境變數**：注入的 `$HOME`、`$TMPDIR` 與網路代理設定；
* **底層執行命令**：完整的啟動命令。

直接將對話方塊中的這些應用配置資訊文本複製下來。

---

### 第三步：前往 GitHub 提交 Issue
1. 訪問 ATBClone 官方 GitHub Issue 頁面：
   👉 **[https://github.com/aitobox/ATBClone/issues](https://github.com/aitobox/ATBClone/issues)**
2. 點選 **"New Issue"** 按鈕。
3. 將您從“分身詳情”對話方塊中複製的應用資訊、終端報錯日誌與應用名稱/版本貼上進來：
   * **應用名稱與版本**：例如 釘釘 v7.5.0
   * **macOS 系統版本與晶片**：例如 macOS 14.5 Sonoma (M2 晶片)
   * **克隆策略**：`hard_clone` 或 `soft_clone`
   * **分身詳情資訊與日誌**：將“分身詳情”對話方塊中的配置內容直接貼上到 Issue 描述中，並附帶 ATBClone“日誌”選項卡中的報錯資訊。

維護團隊將針對該應用進行定向排查與適配，並在後續版本中更新內建規則！
