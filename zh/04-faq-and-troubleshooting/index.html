❓ 常见问题解答 (FAQ)¶

1. 分身会影响原有 App 的数据吗？¶

绝对不会。

ATBClone 在设计上实现了严格的物理级隔离与沙盒容器隔离：

  • 原版母体应用依然读取并写入系统默认的真实路径（如 ~/Library/Application Support/ 或 ~/Library/Containers/<原BundleID>）。
  • 分身应用被限定在其专属的隔离目录中运行（如 ~/ATBClone/Data/<分身名称>/）。
  • 两者同时运行互不抢占本地 SQLite 数据库文件，互不覆盖配置，互不污染缓存。

2. 分身的数据存放在哪里？如何备份与迁移？¶

默认情况下，所有分身的用户数据（本地聊天记录、数据库、Cookie、首选项与缓存文件）均存放在您的用户目录下： ~/ATBClone/Data/<分身名称>/

~/ATBClone/
├── config.yaml           # 全局偏好设置
├── clones.yaml           # 已创建分身元数据注册表
├── recipes/              # 用户自定义规则库
└── Data/
    ├── WeChat2/          # 微信分身 2 的专属数据目录
    │   ├── Home/         # 伪装的 $HOME 目录
    │   └── Tmp/          # 专属临时目录
    └── Telegram-Work/    # Telegram 工作分身数据目录

如何备份与迁移：¶

  • 数据备份：直接将 ~/ATBClone/Data/<分身名称> 文件夹复制或压缩打包备份至移动硬盘或网盘。
  • 换机迁移：在新 Mac 上安装好 ATBClone，将旧电脑的 ~/ATBClone/ 整个目录拷贝至新电脑相同路径下，然后使用相同名称重新克隆一次应用，原有的聊天记录与登录态将被直接识别！

3. 会被官方封禁账号吗？¶

ATBClone 运行在纯粹的 macOS 操作系统环境层。

  • 零逆向篡改 / 零内存注入：ATBClone 不会注入任何动态链接库（如 Frida、Cycript、Xposed 等 Hook 工具），不会修改应用内存或拦截网络数据包，也不会篡改编译好的 Mach-O 机器指令。
  • 纯净环境欺骗：应用本体以原版逻辑运行，只是被重定向了 $HOME 家目录并赋予了新的合法 Bundle ID。
  • 单应用独立 IP 代理：通过为分身配置独立的 HTTP 或 SOCKS5 代理，不同分身可使用完全独立的公网 IP 访问服务器，有效避免多账号在同一 IP 下的高频关联风险。

Important

虽然 ATBClone 提供了最干净安全的操作系统级隔离，但您仍需遵守各平台的用户协议，切勿利用多开进行批量群发、违规外挂或自动化恶意行为。

4. 需要管理员密码 (Root / Sudo) 吗？¶

  • 安装到 ~/ATBClone/Apps（默认推荐）：全程无需管理员密码，免 Root 权限。 所有文件均运行在当前普通用户空间中。
  • 安装到系统全局 /Applications：macOS 会弹出一次系统原生授权窗口，要求输入开机密码以允许向全局系统目录写入文件。

5. 打开分身提示“已损坏，无法打开”怎么办？¶

这是因为 macOS Gatekeeper（门禁系统）为修改过签名的应用打上了隔离扩展属性（com.apple.quarantine）。

解决方法：¶

打开 macOS 终端（Terminal），运行以下命令清理隔离属性： 

xattr -cr "/path/to/您的分身应用.app"
或者在 ATBClone 主界面中选中该分身，点击 "更新"，引擎将自动为您清除隔离属性并重新完成 Ad-Hoc 签名。

6. 如何为分身更换自定义图标？¶

  1. 在访达中打开 ~/ATBClone/Apps，找到您的分身应用。
  2. 选中分身并按下快捷键 Cmd + I（显示简介）。
  3. 将您准备好的 .icns 或 .png 图标文件，直接拖拽到简介窗口左上角的小图标上即可完成替换。

7. 微信/QQ 等通信分身如何在菜单栏显示图标并正常接收消息提醒？¶

微信、QQ 等即时通讯软件支持在 macOS 顶部菜单栏驻留图标并在后台持续接收新消息。

1. 开启菜单栏图标显示：¶

  • 登录分身微信后，按下快捷键 Cmd + , 或在顶部菜单选择 微信 -> 设置（Settings）。
  • 进入 通用（General）设置页面，勾选 「在菜单栏显示微信图标」（Show WeChat in Menu Bar）。
  • ATBClone 引擎会在分身首次启动时自动继承母体微信的基础偏好设置，若母体已开启该选项，分身将自动开启。

2. 后台消息接收机制与通知：¶

  • 后台长连接：由于分身使用 Ad-hoc 重签名，macOS 的 Apple 官方远程推送（APNs）无法直接路由至分身，但微信在后台运行时会通过自身独立的 TCP 长连接（LongLink）实时接收所有私聊与群聊消息。
  • 保持后台运行：日常使用时，直接点击主窗口红色的「关闭」（x）按钮即可关闭窗口，微信分身将继续在菜单栏和后台驻留运行，切勿使用 Cmd + Q 彻底退出。
  • 消息提醒效果：当收到新消息时，菜单栏分身图标将显示未读提示（红点/动画），程序坞（Dock）图标将显示未读数字徽标，并伴随提示音。
  • 系统通知权限：首次运行分身微信时，若系统弹出「是否允许 WeChat 发送通知」，请点击「允许」。亦可前往 macOS 系统设置 -> 通知 中确认已为分身应用开启通知横幅与声音提示。

Tip

底层保障：微信、QQ 等通信软件依赖 ATBClone 的 dylib 原生动态库注入模式（创建分身时请保持 auto 或选择 dylib），以避免 execv 导致进程版本号改变而破坏 macOS 通知中心 (usernoted) 与状态栏 (MenuBarAgent)。如果误选为 launcher 模式，通知横幅和菜单栏图标可能会被系统静默屏蔽。

🩺 系统环境体检 (Doctor 工具)¶

如果分身在创建或签名时遇到异常，可以使用内置的 Doctor (系统体检) 工具排查底层依赖：

+-------------------------------------------------------------+
|  🩺 系统环境体检 (System Doctor)                            |
|                                                             |
|  环境自检项目:                                              |
|  [✔] 处理器架构: Apple Silicon (arm64)                      |
|  [✔] Xcode 命令行工具: 已正确安装 (/Library/...)             |
|  [✔] 代码签名组件 (codesign): 正常可用                      |
|  [✔] Plist 处理器 (PlistBuddy): 正常可用                     |
|  [✔] 应用程序目录权限: 读写正常                             |
|  [✔] 数据存储目录权限: 读写正常                             |
|                                                             |
|  [ 重新体检 🔄 ]                                            |
+-------------------------------------------------------------+
  1. 点击 ATBClone 侧边栏的 "系统体检"（🩺）图标。
  2. 探针将自动校验：
  3. Xcode Command Line Tools (xcode-select -p)：确保 Apple 开发者编译工具已安装，这是 codesign 签名的必要条件。
  4. Codesign 与 PlistBuddy：确认系统底层工具链可用。
  5. 目录读写权限：检查 ~/ATBClone/Apps 和 ~/ATBClone/Data 的写入权限。
  6. 若某一项出现红色警告，根据界面提示进行修复即可（如终端执行 xcode-select --install）。

🐛 发现问题与 GitHub 提报指引（标准排错流程）¶

如果您在多开某个特殊软件时发现无法完成分身，或者分身后打开闪退/报错，请通过以下标准流程提取诊断信息并提交 GitHub Issue：

第一步：在主界面选中异常分身并点击“详情”¶

  1. 打开 ATBClone 主界面。
  2. 在卡片视图或表格视图中，选中出现故障的分身应用。
  3. 点击 "详情"（ℹ️ / 详情）按钮打开“分身详情”窗口。
+-------------------------------------------------------------+
|  ℹ️ 分身详细信息 - WeChat2                                  |
|                                                             |
|  基础配置:                                                  |
|  • 母体应用:   /Applications/WeChat.app                     |
|  • 原始 ID:    com.tencent.xinWeChat                        |
|  • 新分身 ID:  com.tencent.xinWeChat.atbclone.WeChat2       |
|  • 克隆策略:   hard_clone                                   |
|  • 安装目标:   /Users/username/ATBClone/Apps/WeChat2.app     |
|  • 数据目录:   /Users/username/ATBClone/Data/WeChat2        |
|  • 代理设置:   http://127.0.0.1:7890                        |
|                                                             |
|  注入参数与运行环境:                                        |
|  • 启动参数:   --user-data-dir=...                          |
|  • 环境变量:   HOME=..., TMPDIR=...                         |
|  • 执行命令:   env HOME=... /path/to/WeChat.bin             |
|                                                             |
|  [ 关闭 ]                                                   |
+-------------------------------------------------------------+

第二步：复制“分身详情”对话框中的应用信息¶

“分身详情”对话框中清晰列出了该分身的核心运行参数与配置：

  • 基础信息：母体路径、变异后的新 Bundle ID、克隆策略与数据存储路径；
  • 注入参数：透传给二进制的命令行参数；
  • 环境变量：注入的 $HOME、$TMPDIR 与网络代理设置；
  • 底层执行命令：完整的启动命令。

直接将对话框中的这些应用配置信息文本复制下来。

第三步：前往 GitHub 提交 Issue¶

  1. 访问 ATBClone 官方 GitHub Issue 页面： 👉 https://github.com/aitobox/ATBClone/issues
  2. 点击 "New Issue" 按钮。
  3. 将您从“分身详情”对话框中复制的应用信息、终端报错日志与应用名称/版本粘贴进来：
  4. 应用名称与版本：例如 钉钉 v7.5.0
  5. macOS 系统版本与芯片：例如 macOS 14.5 Sonoma (M2 芯片)
  6. 克隆策略：hard_clone 或 soft_clone
  7. 分身详情信息与日志：将“分身详情”对话框中的配置内容直接粘贴到 Issue 描述中，并附带 ATBClone“日志”选项卡中的报错信息。

维护团队将针对该应用进行定向排查与适配，并在后续版本中更新内置规则！
